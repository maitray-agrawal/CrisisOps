# Industrial CrisisOps — Strict Architectural & Coding Rules

## 1. Safety & Physical Actuation Guardrails
- **STRICT SAFETY MANDATE**: LLM outputs must **NEVER** directly actuate physical machinery or perform un-gated destructive database/system actions.
- **HUMAN-IN-THE-LOOP (HITL)**: All response plans generated by AI agents must explicitly require manual human confirmation via the UI before any action is logged or simulated.
- **SIMULATED RESPONSE ONLY**: In this MVP, all response actions must remain strictly simulated within software (updating simulated machine states and telemetry profiles). No real-world PLC/hardware integration is permitted.

---

## 2. Agent Workflow & Orchestration Rules
- **SEQUENTIAL WORKFLOW ONLY**: Agents must execute in a strictly linear, deterministic pipeline: `Signal Correlator -> Root Cause Analysis -> Impact Assessment -> SOP Retrieval & Action Recommendation`.
- **NO AUTONOMOUS AGENT CHAT**: Agents are forbidden from engaging in unrestricted, conversational, or looping multi-agent communications.
- **EXPLICIT SCHEMAS**: Every agent input and output must be governed by an explicit Pydantic model in the backend and TypeScript interface in the frontend.
- **DETERMINISTIC FALLBACK REQUIRED**: Every single agent wrapper must include a deterministic rule-based fallback mechanism that executes immediately if the LLM API fails, times out (>5s), or produces invalid schema outputs.

---

## 3. Technology & Framework Constraints
- **BACKEND STACK**: Python 3.10+, FastAPI, Pydantic v2, SQLite (`sqlite3` or SQLAlchemy core).
- **FRONTEND STACK**: React 18, TypeScript, Vite. CSS via Vanilla CSS or TailwindCSS. Modern high-contrast dark theme dashboard aesthetic.
- **DATABASE**: SQLite (`crisisops.db`) is the only authorized database for MVP persistence. No PostgreSQL, Redis, MongoDB, or cloud database setup.
- **VECTOR STORE / RAG**: RAG must use a lightweight, in-memory keyword/cosine-similarity search over synthetic local markdown files. No heavy vector DB microservices (Milvus, Pinecone, Qdrant).
- **INFRASTRUCTURE**: No Kubernetes, Docker Compose multi-container clusters, external event buses (Kafka/RabbitMQ), or cloud infrastructure setups. Monolithic single-process backend + Vite dev server.

---

## 4. Code Quality & Typing Rules
- **NO UNTYPED CODE**:
  - Python: All function parameters, return values, and data structures must have explicit type annotations. No bare `dict` or `Any` where Pydantic models can be used.
  - TypeScript: Strict mode enabled (`tsconfig.json`). No usage of `any`.
- **ERROR HANDLING**:
  - All API routes must return standard HTTP status codes and structured error responses `{ "error": true, "code": "ERR_CODE", "message": "Explanation" }`.
  - All async calls must be wrapped in try/except blocks with structured fallback returns.
- **REPRODUCIBILITY**:
  - All synthetic data generation scripts must use a fixed random seed (`seed=42`) to ensure 100% deterministic demo execution.

---

## 5. Hackathon MVP Scope Boundaries
- **DO NOT BUILD**:
  - Real PLC / Modbus / OPC-UA hardware protocols.
  - User authentication / multi-tenant RBAC (use static single-operator session).
  - Complex 3D CAD digital twins.
  - Microservice mesh.
  - Continuous MLOps training pipelines.
